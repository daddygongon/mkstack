1. この文書の目的

この文書には，独立gem mkstack の設計判断，移植手順，実施結果を時系列で記録する． 利用者向けの簡潔な説明はルートの README.md に置き，ここには開発過程を残す．

2. 開発方針

  • mkstack は単独実行可能なCLI gemとして開発する．
  • 将来は，公開APIを薄いadapterから呼び出して hc mkstack に統合できる構造にする．
  • Ruby gemの標準配置を守り，実装とテストのパスを鏡写しにする．
  • 旧 c0_mk_stack_dir は参照用archiveとして固定し，archive内では開発しない．
  • 旧実装の挙動を特徴付けるtestを先に作り，機能を小さな責務へ分けながら移植する．
  • docs/ は開発資料であり，配布gemには含めない．

3. directory構成

mkstack/
├── exe/
│   └── mkstack                    # CLI entry point
├── lib/
│   ├── mkstack.rb                 # public load point
│   └── mkstack/
│       └── version.rb
├── test/
│   ├── test_helper.rb
│   └── mkstack/
│       └── version_test.rb        # lib/mkstack/version.rbに対応
├── sig/
│   └── mkstack.rbs
├── docs/
│   ├── readme_mk_mkstack.org      # この作業記録
│   └── archive/
│       └── c0_mk_stack_dir/       # 旧projectの固定snapshot
├── bin/                           # 開発支援用script
├── Gemfile
├── Rakefile
└── mkstack.gemspec

機能の移植時には，責務に応じて次のように同じ相対pathを用いる． 

lib/mkstack/command.rb       <-> test/mkstack/command_test.rb
lib/mkstack/configuration.rb <-> test/mkstack/configuration_test.rb
lib/mkstack/stack_builder.rb <-> test/mkstack/stack_builder_test.rb

実装がまだ存在しない機能の空directoryや空fileは作らず，最初のtestと同時に追加する．

4. 作業履歴

4.1. 2026-11-17 directory構成の初期整理

  • Bundlerのscaffoldを独立gemのrootとして維持した．
  • testを test/mkstack/ 以下へ移し，実装との対応関係を明確にした．
  • scaffoldに含まれていた意図的な失敗testを除去した．
  • 旧projectのcommit bd6633eb7a4602c01672ef8ab027383d06424b65 を docs/archive/c0_mk_stack_dir/ に展開した．
  • archiveの由来を docs/archive/README.org に記録した．
  • docs/ をgem packageの対象外にした．
  • scaffoldの未確定URL metadataを除き，gemをbuildできる状態にした．
  • bundle exec rake test と bundle exec rake build の成功を確認した．
  • buildしたgemに docs/=，=test/=，=bin/ が含まれないことを確認した．

5. 次の作業候補

  1. 旧CLIの入口と主要な利用例を洗い出す．
  2. 最小の mkstack command仕様をtestとして記述する．
  3. exe/mkstack を薄いentry pointとし，処理を lib/mkstack/ 以下へ移す．
  4. 旧scriptを責務別に移植し，対応するunit testを追加する．

5.1. 2026-11-17 Thor CLIへの初期移植

  • runtime dependencyとしてThorを追加した．
  • exe/mkstack を Mkstack::CLI の薄いentry pointにした．
  • 旧Rake taskに対応する kick_off=，=mkdir=，=mk_light_table=，=mk_link=， =mk_canvas=，=rsync_public=，=push subcommandを追加した．
  • rake TASK dry_run 相当の位置引数と --dry-run optionの両方を維持した．
  • 配布用assetを lib/mkstack/templates/=，移植中のscriptを =lib/mkstack/scripts/ へ配置した．
  • 作業directoryを指定する共通option -C PATH と，Rake互換の一覧表示 -T を追加した．
  • 旧 colorize と command_line への依存を除き，Thorと標準libraryだけで構成した．
  • 全subcommandのMinitest::Specを test/mkstack/cli_commands_test.rb に追加した． file生成commandは一時directoryで実行し，外部commandを伴う処理はtest doubleで 呼出順とoptionを検証する．
  • minitest-reporters の ProgressReporter を導入し，実行中のtest名，進捗bar， 完了率，経過時間，残り時間をcolor付きで表示するようにした．
  • colorを使えない環境では MINITEST_REPORTERS_MONO=1 bundle exec rake test で 無色表示に切り替えられる．
  • 設定fileの正本を .hc_config.yaml に統一した．=hc_config.yaml~sample= は 正本へのsymbolic linkとし，code内に別のdefault値を持たせない．
  • kick_off は .hc_config.yaml を生成し，dummy値を実環境の値へ編集するよう 警告する．既存設定は上書きしない．
  • 通常commandは現在directoryから親へ遡り，最も近い .hc_config.yaml の 所在directoryをproject rootとして使う．設定が見つからない場合は自動生成せず， kick_off を案内する．
